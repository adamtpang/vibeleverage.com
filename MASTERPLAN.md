# MASTERPLAN.md: Adam's leverage masterplan

Not the vibeleverage.com product plan. Adam's own plan, using the tool he
built to diagnose himself as the anchor. Written 2026-08-10 from a full
session of real evidence, not an interview.

## 🎯 THE THESIS

Leverage is output divided by one lifetime. Becoming the most leveraged
human alive means maxxing code and media first, because they are
permissionless and compound at zero marginal cost, then letting capital
and labor follow, because those need permission and only work once code
and media already have reach.

## ⚙️ THE MECHANISM

1. Ship media daily. One line, one clip, one episode. 80% and iterate,
   never gated on perfect.
2. Make code public and findable. A repo nobody can see has zero
   leverage no matter how good the code is.
3. Let media discover the code, and let the code prove the media.
4. Compound: media earns audience, audience earns capital, capital buys
   back time for more code and more media. Capital and labor are never
   the starting move.

## 💰 THE RETURN

What is spent: hours, and the discomfort of publishing before it feels
ready. What is returned: leverage, output per hour rises every time
something ships instead of sitting finished but unseen.

**The real, unresolved tension: this is not a capability problem.** Adam
had 46 shipped repos with no index and 5 fully produced podcast episodes
sitting unpublished before this session started. The bottleneck has been
named twice now, independently: it is the moment of hitting send, not
the work before it. Building more tooling does not resolve this tension.
Only sending does.

## 🧭 THE DISCIPLINE

- No em-dashes, anywhere, ever. Recurring hard rule.
- Speed and slope of improvement over perfectionism. Ship at 80%, fix in
  public.
- Every guest gets the same on-record promise: "I'll show you before I
  post it." No episode ships without that guest's actual yes.
- No message, DM, or send goes out without explicit, real-time
  go-ahead, in the moment, not inferred from an earlier instruction.
  Learned the hard way this session.
- Repos are the way, not feeds. Pull, not push. Build a library people
  visit, not content that clogs a timeline.

## 🚫 NOT

- Not capital or labor first. Both are old leverage, both need someone
  else's permission, both plateau.
- Not follower-chasing or vanity metrics for their own sake.
- Not perfectionism-gated shipping.
- Not automating away the guest-consent step or the send decision.
  Those stay human, on purpose.
